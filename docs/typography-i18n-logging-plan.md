# Lyrics Plus 排版、国际化与日志改造计划

## 使用说明

- 每次只执行一个阶段，完成验收后再进入下一阶段。
- 每个阶段都必须更新本文档中的任务状态和交接记录。
- 每个阶段应保持独立、可审查，避免顺手扩大改动范围。
- 按项目约定，阶段执行过程中不运行构建命令。
- 除非当前阶段明确要求，否则不要修改桌面歌词的用户可配置字号行为。

## 总目标

为 Lyrics Plus 建立统一、语义化的 UI 排版体系，支持 `zh-CN` 与 `en-US` 运行时切换，并将开发者日志统一为英文。用户可见文本必须通过 i18n 输出，不能直接复用内部日志文本。

## 全局约束

- 普通 UI 字号使用语义化排版 Token，不随意新增孤立字号。
- 排版 Token 统一使用 `rem`；图标尺寸、动态尺寸等合理例外可以保留 `px`。
- 桌面歌词字号、缩放比例及其他用户可配置的显示参数独立于普通 UI 排版体系。
- 用户可见错误必须支持本地化。
- 内部日志、调试信息和日志上下文统一使用英文。
- 底层错误原因、错误链和堆栈必须保留。
- Rust 后端尽量向前端返回稳定错误码或结构化错误，不以英文日志代替用户提示。
- Apple Music、Spotify、LRCLIB 等产品名和服务名保持官方写法。
- 不机械翻译歌曲名、歌手名、歌词内容、测试歌词样例和外部服务原始响应。

## 阶段 1：建立排版规范与 Token

### 目标

建立稳定的语义化排版体系，但暂不批量迁移页面，避免同时改变规则和使用方。

### 工作范围

- [x] 盘点现有 `font-size`、`line-height`、`font-weight` 和字体族用法。
- [x] 将现有用法按标题、正文、标签、说明文字等语义归类。
- [x] 在全局样式中定义排版 Token。
- [x] 至少覆盖 `caption`、`label`、`body-sm`、`body`、`title-sm`、`title`、`display`。
- [x] 为每个 Token 记录字号、行高、推荐字重和使用场景。
- [x] 明确图标、桌面歌词、动态展示、调试日志等例外类型。
- [x] 检查中英文系统字体回退顺序。

### 非目标

- 不批量替换各页面现有字号。
- 不接入 i18n。
- 不调整桌面歌词字号算法或配置范围。

### 验收标准

- [x] 普通 UI 的常见文字层级均能映射到已有 Token。
- [x] Token 命名表达语义，而不是具体数值。
- [x] 不需要为了某个单独页面立即新增特殊字号。
- [x] 页面现有视觉效果没有被大范围改变。

- 不要求本阶段迁移全部硬编码文案。

## 阶段 5：统一英文日志规范

### 目标

让 TypeScript、Rust 和辅助脚本中的正式内部日志统一为清晰、稳定、可搜索的英文，同时与用户提示彻底分离。

### 日志格式原则

- 使用简洁动作描述，例如 `Failed to restore the main window focus`。
- 失败日志包含操作对象、失败动作及原始错误。
- 同类事件使用一致的动词和术语。
- 不在日志中写面向用户的安抚或操作指引。
- 不吞掉原始错误、错误链或堆栈。
- 条件允许时使用稳定的模块名、事件名或结构化字段。

### 工作范围

- [x] 盘点 `log::debug!`、`log::info!`、`log::warn!`、`log::error!`。
- [x] 盘点 `console.*`、Tauri 日志插件和 `reportFrontendError` 调用。
- [x] 将正式内部日志上下文改为英文。
- [x] 统一主要模块中的动作和对象术语。
- [x] 检查前端错误日志是否保留 stack 或 message。
- [x] 确认用户可见错误仍通过 i18n 输出。
- [x] 区分日志文本与 Rust 返回给前端的业务错误。

### 示例

```text
Failed to sync the native overlay blur effect: {error}
Failed to restore the main window focus: {error}
Artwork download exceeded the 10 MB limit
```

### 验收标准

- [x] 新增和现存的正式内部日志统一使用英文。
- [x] 日志可通过稳定英文关键词搜索。
- [x] 日志仍包含足够的操作上下文和原始错误详情。
- [x] 用户界面不会直接展示未经翻译的内部日志。
- [x] 测试数据和外部原始响应不会被误判为日志而机械修改。
