# 国际化开发规范

## 支持范围与默认行为

应用支持 `zh-CN`、`zh-HK`、`zh-TW` 和 `en-US`，并提供 `system` 语言偏好。`system` 根据 `navigator.languages` 中第一个可识别的语言决定界面语言；无法识别时使用默认语言 `en-US`。

中文地区按文字体系及地区匹配：`zh-HK` 和 `zh-MO` 使用香港繁体中文，`zh-TW` 和 `zh-Hant` 使用台湾繁体中文；`zh-CN`、`zh-Hans`、`zh-SG` 和无地区的 `zh` 使用简体中文。语言标签匹配不区分大小写，并兼容使用下划线的系统标签。

语言偏好保存在应用配置 `app.language` 中。Rust 配置更新后通过 `config://changed` 广播，主窗口、设置窗口、快速歌词窗口、桌面歌词窗口和解锁按钮窗口中的 `AppConfigProvider` 会同步收到新配置。`AppI18nProvider` 随后切换 i18next 语言并更新根元素的 `lang` 属性，不需要重启窗口。

缺失的目标语言条目先回退到 `en-US`。所有语言都缺失的键显示为 `[translation.key]`，不会返回空字符串或导致渲染崩溃。此形式用于开发期暴露遗漏，不应作为正式用户文案保留。

## 文件与翻译键

- i18next 初始化与语言检测：`src/features/i18n/i18n.ts`
- React Provider 与语言状态：`src/features/i18n/I18nProvider.tsx`
- 支持语言注册与资源汇总：`src/features/i18n/resources.ts`
- 简体中文、香港繁体中文、台湾繁体中文和英文资源：`src/features/i18n/locales/zh-CN.ts`、`zh-HK.ts`、`zh-TW.ts` 和 `en-US.ts`
- 翻译资源结构类型：`src/features/i18n/resourceTypes.ts`
- 稳定状态与用户文案映射：`src/features/i18n/userText.ts`
- 翻译键类型声明：`src/i18next.d.ts`

翻译键按“功能域 → 页面或模块 → 具体含义”组织，例如：

```text
settings.app.language.label
quickLyrics.noCandidates
overlay.toolbar.increaseFont
```

键名使用稳定英文语义，不包含具体中文、布局位置或临时数值。`zh-CN` 是键结构基准，其他语言资源必须具有完全相同的结构，TypeScript 会检查缺失键、额外键和错误键名。

语言选择器使用各语言自己的名称，不把语言名称作为翻译键维护。以后新增普通 LTR 语言时，增加前端语言资源及注册信息即可，不需要为语言名称修改已有资源。

用户可见文本进入语言资源；内部日志、调试上下文、歌曲名、歌手名、歌词和外部服务原始响应不得进入语言资源。

配置 JSONC 的字段名和选项值属于开发者可编辑的技术格式。生成注释只维护简体中文和英文：简体中文界面使用中文，其余界面使用英文；设置页外围控件和验证状态仍通过 i18n 本地化。用户自己输入的配置注释保持原样。

## React 用法

组件使用 `react-i18next` 的 `useTranslation`：

```tsx
import { useTranslation } from "react-i18next";

const { t } = useTranslation();

return <button>{t("overlay.toolbar.increaseFont")}</button>;
```

新增键后必须同时补齐所有已支持语言。繁体中文采用台湾常用的软件术语，不做机械式简繁转换。不应把翻译后的字符串传给内部日志，也不应使用内部错误文本直接充当用户提示。

## 插值与复数

动态值使用 i18next 插值，不拼接固定 UI 句子：

```tsx
t("quickLyrics.switched", { source: providerName });
```

数量文本使用 i18next 的 `_one`、`_other` 资源约定，并始终传入 `count`：

```tsx
t("common.units.result", { count: results.length });
```

英语会根据数量选择单复数；中文可以让两个形式保持相同表达。日期、数字和时间格式化优先使用当前有效语言及 `Intl` API，不在翻译字符串中硬编码区域格式。

## 语言切换

普通组件只读取翻译。需要提供语言设置的组件通过 `useAppLanguage()` 或现有设置上下文调用 `setLanguage("system" | SupportedLanguage)`。不要直接调用 `appI18n.changeLanguage()`，否则只会改变当前 WebView，无法持久化或同步其他窗口。

持久化配置接受 `system` 或格式合法的 BCP 47 语言标签，当前版本不支持的标签会在前端安全回退到 `en-US`。这样未来增加前端语言时不需要扩展 Rust 枚举。

解析后的有效语言还会同步到 Rust 原生层，用于更新托盘菜单、动态窗口标题和配置注释。原生层只维护 `zh-CN` 和 `en-US`：仅简体中文界面使用原生中文，繁体中文、英文及未来新增语言都使用原生英文。`system` 的系统语言解析始终由前端统一完成。

## 后端错误边界

Tauri 命令失败会在 `src/shared/api.ts` 转换为 `AppOperationError`。其稳定错误码为 `command.<command_name>`；配置并发冲突由 Rust 返回稳定的 `config.conflict:` 标记，并映射为 `config.conflict`。原始错误保存在 `cause` 中并在转换前写入开发者日志，用户界面只显示本地化提示。

播放器状态由 Rust 返回 `PlaybackErrorCode`，前端在 `userText.ts` 中映射为翻译键。歌词源诊断的原始 `message`、歌词目录扫描的原始 `error` 和配置解析的底层 `message` 只作为诊断详情保留，界面根据稳定的健康状态、扫描阶段或验证状态显示本地化文本，不直接复用内部错误字符串。

## 合理保留的源码字面量

以下内容不是待翻译的普通 UI 文案，可以保留源码字面量：

- `Lyrics Plus`、Apple Music、Spotify、LRCLIB 等产品或服务官方名称。
- `Ctrl`、`Super`、`Alt`、`Esc`、`⌘` 等快捷键名称和符号。
- `DEBUG`、`INFO`、`WARN`、`ERROR` 等固定开发者日志等级。
- 纯图标字符、数学符号、百分号、单位和视觉分隔符；其可访问名称必须继续使用翻译键。
- `userText.ts` 和数据写入边界中的“本地导入”“本地文件”等历史来源标识；这些值用于兼容既有数据，渲染前必须映射到语言资源。

Tauri 托盘菜单和原生窗口标题无法直接调用 React i18next，由 Rust `native_labels()` 集中维护中英文映射。前端先把有效界面语言映射为原生中英语言，再同步给原生层。禁止在其他 Rust 调用点新增散落的用户文案，也不要为新的前端语言扩展原生语言枚举。
