# Lyrics Plus 歌词领域模型 V2

## 目的

本文档冻结 Lyrics Plus 歌词管理 V2 的领域术语和基本边界。后端数据库、公开类型、Tauri 命令、搜索流程和前端文案应使用本文档定义的含义。

本轮管理对象是一首具体歌曲版本（内部类型仍为 `Recording`）：每个平台最多一条曲目，共用一副歌词，各平台保留独立时间偏移。

## 核心术语

### Recording

`Recording` 表示一条具体的音频录音版本，是歌词关联的核心实体。

它可以保存规范标题、规范专辑、时长和版本标签，但不直接保存某个平台特有的 ID。以下情况默认视为不同的 `Recording`：

- 原版、Live、Acoustic、Remix、Remaster；
- Clean、Explicit、Instrumental、Karaoke；
- Radio edit、Sped up、Slowed、Demo；
- 其他会改变音频内容、剪辑或演唱版本的变体。

“同一首作品”不等于“同一录音版本”。本轮不建立 `Work` 或 `Composition` 层，也不尝试表达原唱、翻唱之间的作品关系。

### TrackObservation

`TrackObservation` 表示播放器在某个平台上观察到的一条曲目信息，是一次平台曲目观察记录，不是录音本身。

它至少保留：

- 原始 `track_key`；
- 平台命名空间；
- 原始标题、歌手列表、专辑和时长；
- 观察或抓取时间；
- 指向的 `Recording`。

同一个播放器曲目观察只能指向一个 `Recording`，同一 `Recording` 每个平台最多一个观察。旧重复平台不自动删除，需先在管理器中移出多余曲目。如果证据不足，不应通过旧别名直接把它自动并入已有录音；应保留待确认状态或创建独立录音。

### ExternalIdentifier

`ExternalIdentifier` 表示带命名空间和类型的平台或行业标识，并通过类型化关系指向 `Recording`。

标识至少由以下字段区分：

- `namespace`：例如 `spotify`、`apple_music`、`qq_music`、`netease`、`isrc`；
- `id_kind`：例如 `track_id`、`catalog_id`、`persistent_id`、`songmid`、`recording_id`；
- `value`：标识值本身；
- 关联的 `recording_id`；
- `confidence` 和 `confirmed`。

禁止把不同平台、不同类型的 ID 仅作为一个无类型字符串保存。用户确认过的映射优先级高于推断结果；精确 ID 仍需通过歌词解析才能完成最终应用。

### LyricAsset

`LyricAsset` 表示一份真实的歌词内容或文件，是可被多个绑定引用的资源，不等同于某次搜索结果或某个平台曲目。

资源记录至少描述：

- 来源类别：`managed`、`local`、`legacy` 或 `cache`；
- provider 及 provider item ID（如有）；
- 格式和语言；
- 纯文本、逐行、逐字等时间能力；
- 是否包含翻译或音译；
- 内容指纹；
- 所属歌词根目录及相对路径；
- 当前可用状态。

相同内容指纹只建立一份资源记录，但可以保留多个来源证据。解绑、拆分或修正关联不会删除资源记录或磁盘文件。

### LyricsBinding

`LyricsBinding` 表示一个 `Recording` 与一个 `LyricAsset` 之间的关联。

一个 `Recording` 可以拥有多个候选绑定，但只能有一个默认生效绑定。绑定需要记录：

- 选择来源：用户、自动或迁移；
- 匹配置信度；
- 匹配证据；
- 默认偏移量；
- 是否为当前默认生效资源。

解绑只取消生效关系，不删除 `LyricAsset`、来源证据或原始文件。

### PlatformOverride

现有 `platform_lyric_overrides` 表继续保存各平台时间偏移。未操作的历史歌曲仍兼容读取歌词资源覆盖；关联、移出或重新设置共用歌词时，在同一事务内把旧覆盖资源保留为非默认绑定，清空覆盖资源字段，保留偏移。新流程不再创建平台专属歌词。

## 歌手与署名

歌手信息分为规范歌手实体和录音署名两层：

- `artists` 保存规范歌手名称；
- `recording_artist_credits` 按原始出现顺序保存 `raw_name` 和角色；角色只使用 `lead`、`featured`、`unknown`；
- `artist_aliases` 保存别名及 `confirmed` 状态。

原始歌手名称和顺序不可被规范化结果覆盖。只有 `confirmed=1` 的别名才可以在自动匹配中作为等价名称；中英文名称默认不是同一歌手，必须经过用户确认后才允许建立确认别名。平台缺少参与歌手时只能形成署名子集证据，不能凭空补齐原始署名。

## 实体关系

```text
TrackObservation ──指向──> Recording <──关联──> LyricsBinding ──引用──> LyricAsset
        │                    │  │
        │                    │  └──拥有──> PlatformOverride（按平台）
        └──携带/解析──> ExternalIdentifier
```

关系含义：

1. 播放器先产生 `TrackObservation`，再由身份匹配将其指向 `Recording`。
2. 平台 ID 通过 `ExternalIdentifier` 类型化保存，不能替代 `Recording`。
3. 歌词内容通过 `LyricAsset` 独立保存，再由 `LyricsBinding` 选择和生效。
4. 平台差异通过 `PlatformOverride` 表达，默认情况下继承录音级绑定。

## 歌曲平台关联管理

```text
Recording：具体歌曲版本
├─ Spotify 曲目与精确 ID（最多一条）
├─ Apple Music 曲目与精确 ID（最多一条）
├─ 其他平台（每个平台最多一条）
├─ 默认共用歌词（最多一副，其他资源保留为非默认绑定）
└─ 每个平台的独立时间偏移
```

系统只使用本地已观察的歌曲。已确认的精确平台 ID 直接解析现有关系；其他情况只产生候选，等待用户点击“关联到当前歌曲”。

候选比较覆盖双方全部平台观察，选择最佳有效证据对。普通候选固定要求歌名相似度 ≥90%、歌手相似度 ≥80%、已知时长差 ≤10 秒、版本标签无冲突，且主歌手不能冲突。双方已确认别名参与比较，未确认别名不参与。专辑不作为门槛。用户权重及标题过滤、繁简转换设置用于评分；权重不能改变固定门槛。

原关联、相同跨平台标识属于强证据候选，未通过门槛也展示具体冲突，由用户确认；同平台曲目冲突始终禁止关联。排序依次为原关联、跨平台标识、用户权重综合分、歌词正文相似度、最近观察时间。原关联优先级不改写实际综合分。歌词一致只能提供辅助证据。

“关联到当前歌曲”在一个事务内重新校验候选、迁移全部观察和外部 ID，只确认各观察的精确平台曲目 ID，保留其他标识原确认状态；清除来源标记，迁移歌词绑定及搜索关系。当前默认歌词优先，当前无歌词时采用候选默认歌词。规范化旧覆盖后才清理空候选实体，资源、来源和磁盘文件保留。

“移出当前歌曲”只移动选中的平台观察及其精确 ID 和可确定归属的平台标识，新建歌曲，保留偏移。默认不绑定歌词，也可沿用歌曲共用歌词。来源通过 `split_from_recording_id` 记录，原歌曲成为优先候选，不提供特殊恢复按钮。明确的管理状态阻断旧 `lyric_associations` 回退。旧重复平台中无法确认归属的其他 ID 保留原处。

接口为 `get_song_association_candidates`、`associate_song_candidate`、`detach_platform_track`。不新增表或迁移，不联网采集 ISRC。任一事务步骤失败均回滚。

后端实现位于 `storage/song_manager/{models,identity,candidates,associations,lyrics}.rs`；`mod.rs` 只组织接口。前端详情容器组合独立区域及确认弹窗，完整搜索阶段、来源耗时、淘汰和选择原因保留。

## 版本标签规范

版本判断使用以下规范标签：

`original`、`live`、`acoustic`、`remix`、`remaster`、`clean`、`explicit`、`instrumental`、`karaoke`、`radio_edit`、`sped_up`、`slowed`、`demo`。

标签冲突是自动绑定的硬冲突；标签缺失不是冲突，但不能获得版本匹配分。标题和歌手相似不能单独证明两个 `Recording` 相同。

## 搜索流程与状态

歌词搜索统一按以下顺序推进：

```text
识别歌曲
  → 查找已有绑定
  → 搜索本地目录
  → 搜索在线来源
  → 比较录音版本
  → 自动应用 / 等待选择
```

各状态含义固定如下：

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| `识别歌曲` | 从播放器输入解析平台、曲目元数据和可用外部 ID | 进入已有绑定查询或创建身份匹配上下文 |
| `查找已有绑定` | 查询用户确认的平台映射、平台覆盖和 Recording 默认绑定 | 命中则加载资源；未命中则进入搜索 |
| `搜索本地目录` | 只读当前启用的本地根目录；历史索引仅作为内部迁移兼容数据参与 | 汇总本地候选后继续在线搜索或版本比较 |
| `搜索在线来源` | 只调用当前策略允许的 Provider，收集候选元数据 | 来源完成、超时或失败后汇总候选 |
| `比较录音版本` | 应用版本硬过滤、身份评分和候选分组 | 满足自动条件则自动应用，否则等待用户选择 |
| `自动应用` | 候选已通过身份和歌词解析条件，事务性保存资源与绑定 | 记录搜索摘要并结束 |
| `等待选择` | 存在歧义或候选未达到自动条件，向用户展示候选和证据 | 用户设为歌曲共用歌词 |

后端进度事件和前端文案都应引用上述状态概念；Provider 的成功、超时和失败是来源级结果，不能把单个来源失败提升为整次搜索失败。重新打开详情界面时，应从最近一次搜索摘要恢复当前状态和候选理由。

身份排序使用用户配置的标题、歌手、专辑、时长和版本权重；自动应用阈值、时长满分容差和部分得分容差同样由配置决定。新字段缺失时分别采用 85、2 秒和 5 秒，且满分容差不得大于部分得分容差。歌词解析有效性、精确来源 ID、版本冲突和主歌手冲突仍是程序正确性规则，不提供关闭开关。

Provider 的分级、能力和自动绑定策略属于后端内部信息。设置页只按用户优先级展示扁平来源列表，汽水音乐始终可见并使用自身启用开关；历史根目录也只保留为迁移兼容数据，不作为用户可管理目录展示。

## 关联与数据安全边界

- 用户确认的平台映射和录音归属优先于自动推断。
- 未确认的旧别名只能作为低可信线索或展示证据，不能单独触发自动合并。
- 歌曲关联和移出在事务中调整关系；仅清理迁移完毕的空歌曲实体，不删除歌词资源或磁盘文件。
- `managed`、`local`、`legacy`、`cache` 四类资源存储边界必须保持独立。
- 应用不得自动移动、覆盖或删除 `local`、`legacy` 类型下的文件。
- 本轮不提供歌词正文编辑、逐字打轴、作品层建模、MusicBrainz 主动查询或自定义 HTTP 歌词源。
